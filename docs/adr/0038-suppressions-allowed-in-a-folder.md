# 0038. A project's ADR may allow a suppression in a folder, without its number on each line

- Status: accepted
- Date: 2026-11-22

## Context

[ADR 0028](0028-gate-interface.md) approves a new suppression comment only when the same line names an accepted ADR of the project (`ADR-NNNN`), and one of that ADR's `- Allows: <text>` lines gives text the line contains. Generated code cannot meet that: the line that marks it (`// Code generated by sqlc. DO NOT EDIT.`, which makes `golangci-lint` skip the file), or a comment a generator writes at the top of every file (`/* eslint-disable */`), is written by the generator, and adding an ADR number to it would mean editing generated output after every run. For the `go` profile (#116), the maintainer decided that generated code keeps needing an accepted ADR, and that such an ADR can cover a folder; the gate needs a way to read that.

## Options considered

1. **A path pattern on the ADR's line**: `- Allows in <path pattern>: <text>`. An added line in a file that matches the pattern, and that contains the text, is approved without naming the ADR. The rest of ADR 0028's rule is unchanged.
2. **Keep the number on each line**, and say that one ADR can cover many files: the gate stays as it is, but the developer edits generated output after every run.
3. **No generated code during the MVP**: a mark fails the gate, and the way to allow it waits until after the MVP.

## Decision

Option 1. This adds to the `suppressions` check of [ADR 0028](0028-gate-interface.md):

- In the lines of a project ADR before its first `##` heading, next to `- Status: accepted`, a line `- Allows in <path pattern>: <text>` allows `<text>` in every file whose path, from the repository root, matches the pattern (`**` across folders, `*` and `?` within one name, as in the gate's other patterns). The pattern may be in backticks.
- An added line that matches a suppression pattern passes when it contains such a text and its file matches such a pattern, whether or not it names the ADR. A line that names an ADR is still checked against that ADR's `- Allows:` lines, as before.
- As before, only an ADR that was accepted at the base, or at the newest commit named as `spec`'s, `design`'s, or `conventions`' ([ADR 0032](0032-gate-base-is-where-the-task-branch-left.md)), approves anything, and the ADR folder is a protected path.

## Reasons

- The decision stays an ADR that the architect or the standards role writes and the gate reads at the base, so the developer still cannot approve their own suppression.
- The pattern names where the exception holds, and the text names what it allows, so a reviewer reading the ADR sees the whole exception in one line.
- Generated files keep their marks exactly as the generator writes them, so running the generator again changes nothing the gate cares about.

## Consequences

- `gates/gate.py` reads both forms of the line. The project's ADR template has the optional `- Allows in` line next to `- Allows:`.
- The `go` and `react-spa` profiles' READMEs say how to allow generated code in a folder.
- A broad pattern allows a lot: `- Allows in **: //nolint` approves every `//nolint`. The review and the security review read the ADR, as for any suppression.
